# 复制给 Agent：帮我安装与使用 OBD Platform

适用于普通平台使用者：让 Agent 协助安装设备工具、核对硬件、烧录固件和主题、配置车辆。网站由运营者统一管理，不需要用户部署社区后端。

复制下方代码框中的完整内容，发送给能够访问项目文件和设备的 Agent。执行中需要接线、设备连接或本人验证时，按实际提示操作。

```text
请帮助我安装、配置并使用 OBD Platform，让它在我的 ESP32、
显示屏和车辆上运行。

项目仓库：
https://github.com/Overzsj/OBD-Platform

在线社区：https://shuangoggsccb.icu
网页烧录入口：https://shuangoggsccb.icu/flash

请实际完成能够执行的工作，不要只提供泛泛的安装说明。
先读取项目当前版本的 README、硬件说明、配置说明、
设备工具说明和相关代码，以实际实现为准。

一、理解使用方式

我是一名平台使用者，不是主题社区服务器管理员。

我的目标是：
1. 在电脑上安装并运行设备工具；
2. 根据我的 ESP32 和显示屏选择兼容配置；
3. 烧录合适的固件；
4. 单独选择并烧录主题；
5. 配置适配器、车辆报警阈值和显示量程；
6. 先进行桌面模拟，再验证实际车辆读数。

不要在我的电脑上部署主题社区后端、账号数据库或服务器。
主题社区是供我通过浏览器访问、预览和下载主题的网站。
优先检查在线社区当前功能。网页烧录需要电脑 Chrome/Edge、HTTPS、
USB 选择和备份保存权限，由我本人完成浏览器授权。
仓库代码和在线网站可能版本不同，以实际检查结果为准；
网页不可用时使用仓库中已有的桌面设备工具，不要猜测接口。

二、先确认我的设备与使用环境

先检查电脑环境和已连接设备，再一次性询问仍缺少的信息：

- 电脑操作系统；
- ESP32 的具体型号、Flash 容量；
- 显示屏驱动芯片、分辨率、横竖屏方向；
- 当前接线，是否有触摸和蜂鸣器；
- USB 串口是否已连接；
- ELM327 或其他适配器的型号与连接方式；
- 车辆品牌、车型、年款、发动机和变速箱；
- 已知的高转提示、红线提示及水温报警要求；
- 是否已有需要保留的固件、主题或设备设置。

不知道的参数请标为待确认，不要自行填写猜测值。
能通过只读检查获取的信息，不要反复让我手动提供。

三、先做兼容性判断

检查当前项目实际支持的芯片、Flash、屏幕、分区和主题引擎。

不要把“通用平台”理解为支持所有 ESP32、所有屏幕、
所有蓝牙适配器和所有车辆数据。

如果我的硬件与现有版本不兼容：
- 明确指出具体差异；
- 说明可以通过配置解决，还是需要修改驱动、布局或通信代码；
- 可以先准备修改和编译验证；
- 不要向设备烧录不匹配的镜像；
- 不要通过改一个分辨率字段就宣称完成屏幕适配。

四、准备项目与设备工具

检查是否已有本项目，优先复用正确的现有目录。
没有时获取官方仓库代码，并记录所用版本或 Git 提交号。

安装运行设备工具所需的依赖。
需要从源码编译时，再准备 PlatformIO 和对应工具链，
不要默认安装无关软件或整个开发环境。

避免覆盖我已有的其他项目、固件和个人文件。
不要修改系统代理、全局 Git 配置或其他无关系统设置。

五、接线与烧录

根据核实后的硬件和固件配置，给我一份清晰的接线表，
包含信号名、GPIO、供电电压和共地关系。

接线需要我动手时，明确告诉我先断电。
不能仅根据接口名称判断电压，也不能将 5V 信号接入
仅支持 3.3V 的 GPIO。

烧录前：
1. 重新确认实际连接的串口和芯片；
2. 检查 Flash 容量与分区布局；
3. 对已有设备完整备份，并保存校验值；
4. 检查固件包及主题包的目标、边界和完整性；
5. 告诉我准备写入的版本与模式。

固件和主题分别处理：
- 空白板使用包含必要启动程序和分区信息的完整固件包；
- 已有设备按实际分区选择合适的更新方式；
- 主题写入独立主题区域，不把普通固件 .bin 当作主题；
- 不因为更换主题就无故擦除车辆配置、日志或整片 Flash。

按照项目工具支持的流程执行，写入后完成校验。
备份、烧录或校验失败时停止后续写入，保留错误信息，
不要报告成功。

六、先完成桌面测试

优先使用模拟固件检查：
- 屏幕方向、颜色和布局；
- 转速、车速及主要数据的显示；
- 开机动画、灯条和竖条动画；
- 蜂鸣器启动提示、高转提示和红线提示；
- 主题切换与参数保存；
- 断电重启后的设置保留。

模拟数据必须明确标识，不写入真实车辆日志。
主题预览通过、编译通过、烧录校验通过和实际屏幕显示正常，
分别说明，不能相互替代。

没有接入实车时，不要声称已经完成车辆适配。

七、配置我的车辆与适配器

优先使用标准 OBD 协议自动发现及项目已有的解码能力。

根据我的实际车型调整报警阈值和显示量程，
不要直接沿用其他车辆的断油转速、齿比或温度限制。

区分：
- 显示量程；
- 报警阈值；
- 车辆真实限制；
- 数据解码与单位。

这些设置不能混为一谈。

适配器配置以实际型号和厂商资料为依据。
蓝牙配对成功不等于数据收发成功；
应通过实际请求和响应验证通信。

不要未经确认自动导入未知来源的私有 PID、
批量扫描 CAN 地址、发送写入命令、清除故障码、
修改 ECU 或执行其他车辆控制操作。

八、实车读数检查

只有在我确认已连接车辆、具备测试条件后，
再进行必要的只读验证。

检查连接状态、协议、支持位图和实际响应。
对于每项数据，区分：
- 已正常读取；
- ECU 声明不支持；
- 请求超时或没有响应；
- 数据过期；
- 解码不匹配；
- 尚未验证。

没有读数时，不要用模拟值、估算值或默认值冒充实测数据。
车辆没有对应传感器或不通过当前协议提供数据时，
明确说明软件不能凭空补齐。

需要我启动发动机、重新插拔适配器或观察屏幕时，
给出简短明确的步骤。行驶测试必须由乘员操作电脑，
不得要求驾驶员在驾驶中调试。

九、交付与后续使用

完成后请告诉我：
- 使用的代码版本；
- 设备和屏幕配置；
- 烧入的是模拟版还是实车版；
- 当前主题和主题引擎；
- 报警阈值与显示量程；
- 固件、主题、配置和备份的保存位置；
- 已通过的验证；
- 尚未验证或暂不支持的项目；
- 下次如何启动工具、更换主题和恢复备份。

如果当前无法连接设备，先完成依赖、配置、
编译和模拟检查，再准确告诉我下一步需要接什么、
按什么按钮或提供什么信息。

不要把我的 VIN、适配器密码、设备完整备份、
账号凭据或真实行车日志上传到公共仓库。
```

人工操作步骤见 [小白使用指南](beginner-guide.md)。
